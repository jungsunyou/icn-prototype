UI가 지켜야 할 불변 규칙
  • 금액 불변 — 어떤 화면에서도 총결제금액은 바꿀 수 없다. 수단·구성만 변경.
  • PG만 실동작 — 현금·통장입금·카드(POS)는 시스템 차감 기록일 뿐 실 금전통·외부 연결이 없다. 결제/환불 로딩·확인은 PG 라인에서만 노출.
  • 선결제(OTA) 제외 — 온사이트 변경·분할 수단 선택지에서 숨김.
  • 이력 필수 — 변경·분할·부분환불은 라인 단위로 항상 이력을 남긴다.

화면 동작
  • 단일 ↔ 분할 토글 — 기본은 단일(현행 드롭다운). 분할 선택 시 라인 입력 UI로 전환.
  • 라인 = 수단 + 금액 — 결제수단 추가로 N개 생성, 개수 제한 없음. 동일 수단 중복 허용(PG 2줄 가능).
  • 실시간 잔액 — 남은 금액 = 총결제금액 − Σ라인금액. 0이면 초록, 그 외 주황.
  • 편의 — 마지막 라인 금액을 '남은 금액'으로 자동 채움. 새 라인 추가 시 잔액을 기본값으로 프리필.

결제 실행 시퀀스 · 원자성
  1. 합계 검증 — Σ라인 = 총결제금액, 0원/빈 라인 없음.
  2. PG 라인 실제 승인 — 리스크 있는 PG를 먼저 처리. 로딩 표시.
  3. 비PG 라인 차감 기록 — 모든 PG 성공 후에만 현금·통장입금·카드(POS) 기록.
  4. 주문 결제완료 커밋 — 라인 전체를 결제완료로 확정, 영수증 발행.
실패 처리 (PG 실패 = 오류)
  • PG 승인 실패 → 오류 배너 노출, 주문은 미완료 유지.
  • 이미 승인된 다른 PG 라인은 자동 취소(void).
  • 비PG 라인은 아직 기록 전 → 롤백 불필요. 부분 성공 꼬임 없음(전부 성공 or 전부 미확정).
  • 사용자는 PG 재시도 또는 해당 라인 수단 변경 후 재실행.
